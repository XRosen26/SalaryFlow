# 薪流 Android 产品需求 V1

版本：0.4　状态：可安装预览版已构建，待持续真机验收　更新：2026-09-13

## 1. 产品目标

让个人在手机上用尽可能少的步骤完成记账、查看本期可用预算和确认资金位置，并保持收入、支出、转账、退款、预算与账户余额只计算一次。

目标用户是主要使用 Windows PC 管理完整财务、同时需要在外快速记录与查看的人。首版也是一个可独立使用的离线个人账本，不要求注册登录。

## 2. 核心场景

1. 解锁后立即看到“当前可安心支出”、本期剩余预算、近期账单和账户余额。
2. 单手按类型、分类、金额、账户和日期快速记一笔支出或收入；金额输入支持 `+ - * / ( )`，保存前展示计算结果。
3. 选择来源账户、分类和实际发生日期，余额不足时明确提示并阻止支出或转账。
4. 管理工资周期或自然月预算，查看分类执行率和超支风险。
5. 工资到账后，根据预算缺口、消费账户余额和储蓄目标形成分配计划，再记录真实转账。
6. 通过完整备份文件在手机和桌面之间迁移账本；恢复前校验并自动保存恢复点。

## 3. 产品原则

- 首页优先回答“还能花多少、钱在哪里、接下来要付什么”。
- 高频操作一层可达，危险操作有明确对象、影响和确认。
- 交易只保存一次；统计按 `transaction_date` 动态查询，预算归属由交易发生日匹配预算周期。
- 转账只改变账户位置，不计收入、支出或储蓄；退款关联原支出并抵减原分类净支出。
- 金额以整数分保存，所有计算先使用整数或有理数，最后一步四舍五入到分。
- 本地优先、默认无账号；导出的备份被视为敏感文件。

## 4. P0（首个可用 Android 版本）

- 首次启动：预算口径、工资日、默认账户、初始余额、隐私设置。
- 首页：本期摘要、快捷记账、近期交易、待付账单、快捷入口。
- 交易：收入、支出、转账、退款；新增、编辑、软删除、历史记录；金额算式。
- 账户：动态新增/编辑/归档；工资、主要消费、主要储蓄、理财估值角色；单账户金额可见性。
- 预算：系统初始模板、个人默认预算、当前周期预算；当前周期与默认预算分别保存。
- 周期：工资周期/自然月；工资日规则立即、下周期或指定日期生效。
- 工资分配：来源工资、计算上限、消费补足、储蓄和资金缺口说明；确认后生成转账记录。
- 固定账单：多个月度/周度账单、到期确认和跳过本期。
- 基础分析：时间范围、收支趋势、分类占比、账户结构。
- 数据：JSON 完整备份、校验、恢复点、恢复、清空账本。
- 中文界面、六套配色、跟随系统/固定浅色/固定深色、首页帮助入口、触屏可访问性、Android 返回手势和自适应布局。
- 统一日期选择器和多格式输入归一化；键盘不得遮挡当前输入字段。

## 5. P1（Android 首版稳定后）

- 英文界面开关与全量翻译巡检。
- 生物识别/PIN 解锁、后台遮挡金额、截图保护选项。
- 本地账单通知、桌面与手机局域网传输、CSV 导入导出、更多分析。
- Android 小组件与快速记账捷径。

## 6. P2（后续平台与服务）

- 经用户确认后评估端到端加密同步、冲突合并和多设备操作日志。
- iOS 适配与发布；HarmonyOS 原生/跨平台方案单独评估。
- 银行账单识别、自动分类、共享账本。

## 7. 暂不纳入首版

- 实时云同步、联网银行、投资交易撮合、税务或理财建议。
- 将桌面数据库文件直接在两个设备间同时编辑。

## 8. P0 验收状态

已通过：类型检查、金额/日期/预算色阶/数据库 schema 自动化测试、Expo 21 项健康检查、Android release 构建、Lint Vital、V2 签名、包名与 API 检查；安装包资产检查未发现个人账本数据。应用无联网、悬浮窗和旧外部存储权限，系统云备份关闭。

真机待验收：Android 7/10/13/16 中可取得设备上的代表版本；冷启动、锁屏恢复、键盘遮挡、系统返回、深浅色、大字体；收入/支出/转账/退款往返；完整备份恢复；1 万笔流水性能。完成这些测试后才把 0.1.0 从“预览”改为“稳定”。

## 9. 已作出的产品决定

- 子项目位置为 `mobile/`；Android 与桌面端同仓库、分构建维护。
- Android 应用 ID 固定为 `com.xrosen26.salaryflow`。
- 第一阶段以完整备份迁移代替多端实时同步，防止未定义冲突导致错账。
- Android 先完成并稳定，再决定 iOS；HarmonyOS 另行评估，不预设与 Expo 完全共用。

## 10. 后续需要用户参与的决定

这些决定不阻塞本地 MVP，但在对应功能开始前需要用户确认：

1. 分发方式：继续个人侧载，还是上架 Google Play；若上架，需要开发者账号、正式签名密钥保管方式和商店隐私资料。
2. PC/手机协作：维持完整备份整库替换，还是开发 OneDrive、WebDAV 或自建服务同步；选择同步时还需确认冲突解决规则。
3. 隐私锁：是否加入生物识别/PIN、后台金额遮挡和截图保护；同时确认忘记 PIN 或生物识别失效时的恢复策略。
4. 固定账单通知：是否允许系统通知、提前几天提醒、错过后是否重复提醒。
5. 加密备份：由用户自设密码还是设备密钥；需要先确定遗失密钥时是否接受无法恢复。
6. English 在中文版真机验收后进入 P1；iOS 与 HarmonyOS 按用户已经确定的顺序后续评估。
